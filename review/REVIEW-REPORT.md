# 최종 검토 보고: org-chart-local.html, 2026-10-16 ~ 2026-10-19 기능

브랜치 `cloud/orgchart-final`, 검토일 2026-10-19. 대상은 `org-chart-local.html` 한 파일이며, 판정 스크립트·기준 파일·러너는 손대지 않았습니다.

## 1. 결론

- 일곱 기능을 함께 돌려 본 결과 **사용자가 실제로 겪는 결함 6건**을 찾아 모두 고쳤습니다. 커밋 7개(결함 6건, 그중 3.5는 후속 보정 1건 포함), 변경 19줄 추가 / 8줄 삭제.
- 가장 큰 것은 두 가지입니다. (1) 가로 방향(왼쪽에서 오른쪽, 오른쪽에서 왼쪽)에서 넓은 직속 카드(mc 3-4)를 부모의 하위 버스 선이 가로지릅니다. (2) TF 유형 하위 조직이 l2/l3 형제와 섞이면 자동 배치를 두 번 누를 때 자리가 왼쪽 끝에서 오른쪽 끝으로 튀고, 수정 모달의 "하위 조직 순서" 목록이 차트 순서와 달라 그 카드를 옮길 수 없습니다.
- 나머지 넷은 옵션 초기화가 인원 수 옵션을 되돌리지 않는 것, localStorage가 막힌 환경에서 옵션 섹션을 접고 펼 수 없는 것, 검색이 카드에 보이는 "팀장(겸)"을 못 찾는 것, 관리자 상태로 인쇄하면 인원 수 알약이 오른쪽 끝에서 29px 떨어져 찍히는 것입니다.
- 판정 결과: 수정 전후 모두 **29/29**(UTF-8 로케일), 기준 페이지 판정 **BASE RESULT OK 8/8**. 각 커밋 시점의 판정도 모두 통과했습니다(5절).
- 고치지 않은 발견 4건은 4절에 이유와 함께 적었습니다. 그중 수정 모달이 카테고리에 없는 직무·직책·분야 값을 저장 시 지우는 문제는 이번 기능 범위 밖의 오래된 동작이지만 데이터가 지워지는 일이므로 별도 확인을 권합니다.

## 2. 환경

- `npm i playwright@1.55.0`은 됐지만 `npx playwright install chromium`은 다운로드가 차단됐습니다(Download failure). 컨테이너에 미리 설치된 Chromium 141 (Playwright build 1194)을 1.55가 찾는 1187 폴더 이름으로 심볼릭 링크해 썼습니다. 판정은 Chromium 141에서 돌렸고, 기준 파일을 만든 Chromium 140과 한 단계 차이입니다.
- 첫 실행에서 `reg-r-exp`만 DIFF가 났는데 내용은 PNG 내려받기 파일 이름이 `조직도-시트 1-...png`가 아니라 `download`로 온 것 하나였습니다. 컨테이너에 로케일이 없어(`LANG` 비어 있음) Chromium이 한글 파일 이름을 버린 것으로, 기준 참조 페이지(r17, r24)도 같은 환경에서 똑같이 `download`가 나오고 `LC_ALL=C.UTF-8`을 주면 이름이 그대로 옵니다. 후보 결함이 아니라 환경 문제이므로 이후 판정은 UTF-8 로케일로 돌렸습니다.
- 데이터는 `review/fake-org.json`(판정용)과 `review/fake-org-concurrent.json`(겸직 7명, 제 점검용)만 썼습니다. 내장 기본값(로고 글자, 카테고리, 예시 조직)은 비어 있는 그대로입니다.

## 3. 수정한 결함

각 항목은 재현 단계, 원인, 수정, 커밋 순입니다. 모든 수정 뒤에 `node review/run.mjs`를 돌렸고(5절), 페이지는 콘솔 오류 없이 열립니다.

### 3.1 옵션 "초기화"가 인원 수 옵션을 되돌리지 않음 (기능 1·4·7)

- 재현: 관리자 → ⚙ 옵션 → 인원 수 섹션에서 위치를 "모서리 배지", 크기 13px, 가로 여백 22px, 겸직을 "제외"로 바꿈 → 초기화 → 확인. 패널이 다시 열리면 인원 수 섹션 값이 그대로이고 카드의 알약도 그대로입니다. "표시" 체크를 끈 상태였다면 초기화 뒤에도 알약이 안 보입니다.
- 원인: `resetOptions()`의 `Object.assign(OPT,{...})`에 `showCnt`, `cntPos`, `cntColor`, `cntCc`, `cntSize`, `cntDx`, `cntDy`가 없었습니다. 기능 1과 4가 옵션을 추가하면서 초기화 목록을 함께 늘리지 않은 것입니다.
- 수정: 일곱 키를 초기화 목록에 넣었습니다. 50ms 뒤 다시 열리는 `openOptions()`가 `_setCntCtl()` → `applyCntStyle()`로 CSS 변수와 컨트롤을 맞추므로 그 외 변경은 없습니다.
- 커밋: `e3afe1c` options: reset (초기화) also restores the head-count pill options

### 3.2 localStorage가 막히면 옵션 섹션을 접고 펼 수 없음 (기능 7)

- 재현: 저장소가 막힌 브라우저(localStorage 접근이 예외를 던지는 프로필, 회사 PC의 임베디드 뷰어에서 가능한 상황)로 열기 → 관리자 → ⚙ 옵션 → "글꼴" 제목 클릭. 아무 변화가 없습니다. 기본으로 열린 섹션(배치·카드·인원 수)은 접을 수도 없습니다.
- 원인: `toggleOptSec()`이 새 상태를 localStorage에 쓰고 `applyOptSecs()`가 localStorage를 다시 읽어 적용합니다. 쓰기가 실패하면 읽기는 항상 기본값을 돌려주므로 클릭이 무효가 됩니다. 판정 `u-opt` P5는 "막힌 저장소에서도 패널이 열린다"까지만 봅니다.
- 수정: `_optSecLoad()`가 localStorage를 읽을 수 있으면 지금처럼 저장소 값을 쓰고, 읽기가 예외를 던질 때만 모듈 변수 `_optSecMem`에 든 세션 내 상태를 돌려줍니다. 토글은 그 객체를 바꾸고 저장은 지금처럼 try로 시도합니다. 저장소가 정상이면 동작이 같고(새 페이지에서 상태 유지, 바깥에서 지운 상태도 반영), 막혀 있으면 세션 안에서 접고 펼기가 동작합니다. 읽기는 되는데 쓰기만 실패하는 경우(용량 초과)는 다음에 패널을 열 때 저장소 값으로 돌아가는데, 드문 경우라 그대로 두었습니다.
- 메모: 처음 작성한 버전은 상태를 메모리에만 두고 저장소를 다시 읽지 않아 판정 `u-opt` P5(페이지가 뜬 뒤 `localStorage.clear()` → 기본 상태 기대)가 RED가 났습니다. 전체 판정에서 잡아 위 설계로 바꾸고, 그 뒤 커밋들을 다시 올렸습니다(브랜치 히스토리 재작성, 강제 푸시 1회).
- 커밋: `6ff6086` options: section fold state works when localStorage is blocked

### 3.3 검색이 카드에 보이는 "팀장(겸)"을 찾지 못함 (기능 4)

- 재현: 겸직 데이터로 열기 → Ctrl+F → "겸" 또는 "팀장(겸)" 입력. "0건"입니다. 카드 직무 줄, 목록 보기, 툴팁은 모두 "팀장(겸)"으로 보여 주는데 검색만 못 찾습니다. "팀장"은 7건이 나옵니다.
- 원인: `srchApply()`가 원본 필드 `m.f`("팀장")와 비교하고, 화면이 쓰는 `jobText(m)`("팀장(겸)")은 쓰지 않았습니다.
- 수정: 카드 판정과 행 강조 두 곳에서 `srchHas(m.f,q)`를 `srchHas(jobText(m),q)`로 바꿨습니다. 직무가 비어 있는 겸직("겸직" 표시)도 같이 찾힙니다.
- 커밋: `a03cef6` search: match the job line as displayed (팀장(겸), 겸직)

### 3.4 가로 방향에서 넓은 직속 카드를 부모의 하위 버스가 가로지름 (기능 2·5)

- 재현: 가상 본사 01(fp)의 하위 팀 4개를 "상위 카드 옆에 붙이기"로 두고 인원 열 수를 3·4열로 → 옵션 차트 방향을 "왼쪽에서 오른쪽으로" → 자동 배치. 직속 카드 4장이 부모 아래에 쌓이는데, 부모에서 prodhq·foodhq로 가는 세로 버스 선이 그 네 장 위를 지나갑니다. 상단 배지가 "⚠ 배치 점검 4건"(선이 카드를 지남)이 됩니다. "오른쪽에서 왼쪽으로"도 같습니다. 세로 방향은 문제 없습니다.
- 원인: `_drawConnsSide()`가 버스 세로선 x를 부모 카드 자체의 바깥 가장자리와 가장 가까운 자식 사이의 중간으로 잡습니다. `_sideLayout()`은 열 폭에 직속 카드 폭을 포함하므로 자식은 멀리 가지만, 버스는 부모(228px) 기준으로 계산되어 876px 직속 카드 위로 떨어집니다.
- 수정: 부모 바로 아래 같은 열에 쌓인 직속 카드(기존 엘보 조건과 같은 판정) 중 가장 넓은 카드의 바깥 가장자리를 기준으로 버스 x를 잡습니다. 직속 카드가 부모와 같은 폭이면 결과가 이전과 같습니다. 부모에서 나가는 짧은 가로 선과 히트 영역은 그대로입니다.
- 커밋: `8f8b7f8` connectors: sideways child bus clears wide beside cards stacked under the parent

### 3.5 TF 유형 하위 조직의 순서가 자동 배치마다 바뀌고 순서 목록으로 옮길 수 없음 (기능 6)

- 재현: 시트 2에서 o_p1(l2) 아래에 l3 팀 5개와 TF 유형 카드 1개를 둠 → 자동 배치. TF 카드는 타입 행(4)이 형제(3)보다 한 줄 아래라 아래 행 맨 왼쪽에 놓입니다. 자동 배치를 다시 누르면 같은 카드가 맨 오른쪽으로 이동합니다. o_p1 수정 모달의 "하위 조직 순서" 목록은 TF 카드를 맨 끝에 보여 주고(차트는 맨 왼쪽), 목록에서 위로 올려 저장해도 변화가 없으며 아래로 내릴 자리는 아예 없습니다.
- 원인: 형제 정렬 규칙 "모두 leaf이고 y가 다르면 y 우선(읽는 순서)"은 줄바꿈된 같은 타입의 leaf를 위한 것인데, 타입 행이 다른 형제에도 적용됐습니다. 아래 행의 카드는 항상 마지막으로 정렬되므로 배치가 수렴하지 않고, 같은 규칙을 쓰는 `_ordTree()`의 목록도 차트의 x 순서와 어긋납니다.
- 수정: 읽는 순서 규칙을 "같은 타입의 leaf 두 장이 서로 다른 행에 있을 때"로 좁혔습니다. 줄바꿈된 그룹은 같은 타입이 여러 행에 걸치므로 이전처럼 읽는 순서를 쓰고, 타입 행 차이만으로 혼자 아래 행에 놓인 카드(TF)는 x 순서를 따릅니다. `autoLayout()`, `_ordTree()`, 목록 보기 `tvOrder()` 세 곳을 같은 조건으로 맞췄습니다. 수정 뒤에는 두 번째 자동 배치에도 자리가 유지되고, 목록 순서 = 차트 순서이며, 목록에서 TF 카드를 1번째·3번째로 옮기면 그대로 반영됩니다.
- 커밋: `b271156` layout: siblings on different type rows keep their x order (TF child reorder), 그리고 후속 보정 `0a7f351` layout: reading order needs same-type leaves on different rows. 첫 커밋의 조건("형제 타입이 모두 같을 때만 읽는 순서")은 l2·l3 leaf가 섞인 줄바꿈 그룹에서 자동 배치마다 순서가 한 칸씩 돌아가는 회귀를 만들었고, 제 추가 점검(혼합 타입 줄바꿈 3회 반복 배치)에서 잡아 두 번째 커밋으로 바로잡았습니다.

### 3.6 관리자 상태로 인쇄하면 인원 수 알약 위치가 다름 (기능 1)

- 재현: 관리자 → Local ▾ → 인쇄 / PDF. 미리보기에서 알약이 카드 오른쪽 끝에서 36px 안쪽에 있습니다. 읽기 전용으로 인쇄하거나 PNG로 내려받으면 7px 자리입니다.
- 원인: 알약은 관리자 모드에서 ✏ 버튼 자리(29px)를 비워 둡니다. 인쇄 CSS는 `.nact`를 숨기지 않지만 버튼은 불투명도 0이어서 보이지 않고, 알약만 빈 자리를 피한 채 찍힙니다.
- 수정: `@media print`에 `.ncnt{right:calc(7px + var(--cnt-dx,0px))}` 한 줄. 모서리 배지는 더 구체적인 선택자가 있어 그대로입니다.
- 커밋: `a3108ec` print: head-count pill sits at the read-only position

## 4. 고치지 않은 발견

1. **수정 모달이 카테고리에 없는 직무·직책·분야 값을 저장 시 지움.** 카테고리가 비어 있는 상태(이 저장소의 내장 기본값, 또는 데이터 패널에서 항목을 지운 뒤)에서 카드를 수정하고 저장하면 그 카드 멤버의 직무·직책·분야가 모두 ""가 됩니다. `mkCatSel()`이 목록에 없는 값을 "미입력"으로 바꾸기 때문입니다. 가장 오래된 참조 페이지(r07)부터 같은 동작이고 이번 일곱 기능과 무관해 두었지만, 소유자 파일처럼 카테고리가 채워진 환경에서도 카테고리를 하나 지우면 같은 일이 일어나므로 별도 과제로 확인을 권합니다.
2. **CSV는 `mc`(인원 열 수)·`kl`·`kn`·`ad`·`ac`·`aside`를 내려받지 않음.** CSV 왕복 뒤 넓은 카드는 1열로 돌아옵니다. README가 CSV를 조직·인원·연결 데이터 전용으로 못박고 설정 왕복은 JSON으로 안내하므로 문서대로입니다. 겸직(`concurrent`) 열은 왕복이 맞습니다.
3. **IndexedDB가 응답하지 않을 때 파일 선택 모달이 1.5초 늦게 닫힘.** `_connectHandle()`이 핸들 저장(`_idb.set`)의 1.5초 타임아웃을 기다린 뒤 모달을 닫습니다. 연결·불러오기·저장은 정상이고 다음 방문에 핸들이 기억되지 않는 것은 IndexedDB 없이는 해결할 수 없습니다. 드문 환경의 1.5초 지연이라 그대로 두었습니다.
4. **비교 모드(⇄ 비교)는 겸직 플래그 변화를 "변경"으로 잡지 않음.** 직위·직무·상태만 비교합니다. 비교 기능은 이번 범위 밖이고 겸직 전환은 드물어 두었습니다.

판정 스크립트에 잘못된 점은 찾지 못했습니다. `reg-r-exp`의 DIFF는 2절의 로케일 문제입니다.

## 6. 점검했지만 이상이 없던 것

제 스크립트(`_adoptData` → `_finishLoad` → `switchSheet`, 관리자 `ADMIN=true; applyRO()`)로 다음을 확인했습니다. 모든 회차에서 페이지 오류·콘솔 오류 0건.

- **넓은 직속 카드 2·3열(세로 방향)**: fp에 mc 3·4 직속 카드 4장을 ac 2/3, 위치 오른쪽/왼쪽/좌우 나눔으로 자동 배치. 겹침·선 통과·끊김 0, 첫 행은 모두 부모 헤더 중심 아래, 부모 위로 올라가는 선 없음. side 유형(점선)과 aside가 섞인 경우, 직속 카드와 일반 하위 조직을 함께 가진 부모(prodhq)도 정상이며 일반 하위 버스는 직속 카드 아래에서 시작합니다. 직속 카드를 끌어 다른 행으로 옮긴 뒤에도 끝이 허공에 남는 선은 없습니다.
- **가로 방향**: 3.4 수정 뒤 ac 2/3 × 위치 세 가지 × 왼쪽/오른쪽 방향 모두 점검 0건. 가로 방향에서는 직속 카드가 부모 아래 한 열로 쌓이며 ac는 쓰이지 않는데, 공간이 세로로 흐르는 방향이라 그대로 두었습니다.
- **순서 목록**: 넓은 카드(mc 4)·접힌 형제(o_p2 접힘 유지)·TF·side 직속 카드가 섞인 부모에서 ▲▼와 드래그로 순서를 바꾸고 저장 → 되돌리기 한 번에 순서와 위치가 복원되고 다시 하기로 재적용. 되돌리기 스택은 저장 한 번에 한 단계만 늘어납니다. 가로 방향에서는 목록이 y 순서를 따르고 저장 시 반영됩니다. 좌우 나눔(ad=B) 직속 카드 순서도 오른쪽 그룹 → 왼쪽 그룹 순으로 일관됩니다.
- **겸직**: 카드 "팀장(겸)", 알약 "2명 +1겸", 포함 "3명", 제외 "2명"; 목록 보기 행과 멤버 줄, 툴팁(직무 팀장(겸)) 일치. 현황 패널 총원 58 = 65 - 7, 직무·직책 탭과 접힌 제목 "인원 현황 58명"도 한 사람 한 번. PNG는 알약을 네 위치 모두 화면 규칙과 같은 자리·색으로 그립니다. 인쇄 준비·복원 정상. CSV 내려받기에 `concurrent` 열 7건, 다시 가져오면 겸직 플래그 유지. 수정 모달의 겸직 체크가 저장에 반영됩니다. 읽기 전용은 알약 7px, 관리자는 36px.
- **알약 크기·오프셋**: 위치 4종 × (크기 8/9/12/14, 가로 여백 -30/0/60, 세로 -30/0/30) 조합에서 글자 잘림 없음. 사용자가 극단 오프셋을 주면 헤더 밖으로 나가거나 ✏ 버튼과 겹치는데 이는 설정값의 결과입니다. 기본 오프셋에서는 "모서리 배지" 크기 12 이상일 때 관리자 모드에서만 ✏ 버튼 모서리와 몇 px 겹치고, 알약이 클릭을 받지 않아 동작엔 영향이 없어 두었습니다. 접기 토글은 마우스를 올릴 때만 보이고 접힌 카드는 "+16"을 항상 표시, 발표 보기에서는 알약 7px·버튼 숨김, 15% 줌에서 토글은 4배로 커져 유지됩니다.
